# Inspection AI

Веб-приложение для автоматизированной инспекции фото- и видеоматериалов с помощью модели компьютерного зрения YOLO. Помогает анализировать материалы обследования, находить объекты целевого класса, сохранять визуальные доказательства обнаружений и формировать сводные отчёты.

## Описание проекта

Оператор загружает фотографии, видео или ZIP-архив с материалами, указывает зону, имя оператора и порог уверенности модели. Node.js ставит задачу в очередь и передаёт её отдельному Python-процессу с Ultralytics YOLO. Результаты распознавания — классы, уверенность, координаты рамок и индексы кадров — сохраняются в SQLite и отображаются в интерфейсе вместе с размеченными изображениями или видео.

Изображения из архива обрабатываются как один анализ и сводный отчёт. Для завершённых задач доступны статистика, журнал, кадры с детекциями, проверка/смена статуса обнаружений и экспорт в JSON или PDF. PDF содержит кадры, на которых модель обнаружила объекты.

Это вспомогательный инструмент: качество зависит от обученной модели и её параметров, поэтому результаты нужно проверять оператору. Кадастровая карта показывает данные НСПД и OpenStreetMap; доступность внешних сервисов и актуальность сведений зависят от их владельцев.

## Возможности

- Загрузка фото и видео, до 20 файлов за раз, ZIP-архивы с вложенными папками.
- Последовательная фоновая обработка YOLO; кадры с рамками и размеченные видео.
- Анализ публичных ссылок Google Drive и видеопотоков RTSP/RTSPS/HTTP/HTTPS.
- Статистика, логи, сводные отчёты, статусы проверки обнаружений.
- Экспорт отчётов и всех кадров с детекциями в PDF, а также JSON.
- Кадастровая карта НСПД с поиском по кадастровому номеру или адресу, отображением границ и сведений объектов.

## Архитектура

- `server.js` — Node.js HTTP-сервер и API, встроенный SQLite, загрузка и обработка архивов, очередь задач, отчёты и раздача файлов.
- `yolo_worker.py` — Python worker для инференса Ultralytics YOLO. Получает настройки через stdin и возвращает события в формате JSON Lines.
- `run_yolo.py` — отдельный CLI для локального анализа, сайтом не используется.
- `templates/index.html`, `static/app.js`, `static/style.css` — веб-интерфейс.
- `static/cadastre.js`, `nspd_client.js` — карта Leaflet и ограниченный same-origin прокси поиска/WMS НСПД.
- `inspection_data/` — локальная SQLite-база, загрузки и результаты. Не публикуйте реальные данные из этой папки.

Для кадастрового слоя требуется доступ Node.js-сервера к `nspd.gov.ru`; базовая карта загружается с серверов OpenStreetMap. Поиск и кадастровая подложка не работают без доступа к соответствующим внешним сервисам. Leaflet подключён локально из npm-зависимостей.

## Требования

- Node.js 22.13 или новее.
- Python 3.10+ и пакеты из `requirements.txt`.
- Файл модели YOLO, по умолчанию `C:\Users\sasak\Desktop\best.pt`.

## Запуск в Windows PowerShell

```powershell
npm.cmd install
py -3 -m pip install -r requirements.txt
npm.cmd start
```

Откройте `http://127.0.0.1:5000`. Для другой модели задайте путь перед запуском:

```powershell
$env:YOLO_MODEL_PATH = "D:\models\best.pt"
npm.cmd start
```

Страница входа включается при задании `APP_USERNAME` и
`APP_PASSWORD`. Для сохранения учётных данных только на этом компьютере создайте
в корне проекта неотслеживаемый файл `.auth.local.json`:

```json
{
  "username": "Admin",
  "password": "задайте-свой-пароль"
}
```

Файл исключён из Git; секреты не публикуются вместе с исходным кодом.
Вместо файла можно задать переменные окружения `APP_USERNAME` и `APP_PASSWORD`.
После входа сервер выдаёт сессионную HttpOnly-cookie сроком на 8 часов; кнопка
«Выйти» завершает сессию. При работе через HTTPS cookie получает флаг `Secure`.
Для внешнего доступа используйте `start-public.ps1`: он задаёт отдельный
случайный пароль и не использует локальную конфигурацию. Не используйте короткий
локальный пароль в публичной сети.

Для Python-команды, отличающейся от `py -3`, используйте `PYTHON_EXECUTABLE`. `INSPECTION_DATA_DIR` меняет каталог базы/файлов, а `PORT` — порт сервера.

## Дообучение YOLO

В основном интерфейсе нажмите **«Дообучение модели»** — откроется отдельная
вкладка Streamlit. Если страница обучения ещё не запущена, откройте второй
терминал в папке проекта и выполните:

```powershell
npm.cmd run start:training
```

Затем перейдите на `http://127.0.0.1:8501`. Streamlit привязывается только к
localhost. Максимальный размер ZIP-датасета и загружаемых весов `.pt` —
10 ГБ для каждого файла; распакованный датасет ограничен 50 ГБ. Streamlit
временно держит загрузку в памяти, поэтому для крупных файлов необходимы
достаточная RAM и место на диске. Можно также указать путь к базовым весам на
этом компьютере.

Конвертер автоматически распознаёт YOLO Detection (`data.yaml`), COCO JSON,
Pascal VOC XML, LabelMe JSON и CVAT XML и создаёт структуру YOLO Detection.
Для исходных разметок без явного разделения train/val применяется
детерминированное разделение 80/20. Если в датасете несколько форматов,
неоднозначные или неполные labels, приложение выдаёт ошибку вместо
непредсказуемого преобразования. ZIP и пути в разметке проверяются до
обучения; поддерживаются вложенные каталоги. Каждый файл разметки ограничен
1 ГБ, число файлов — 100 000.

Для прямой загрузки COCO в форме обучения выберите JSON с разметкой и ZIP с
изображениями, на которые ссылаются поля `file_name`. Этот режим создаёт
Detection-разметку из COCO bbox (сегментационные полигоны для обучения сайта
не используются), пропускает `iscrowd` и отсутствующие изображения и
детерминированно делит данные на train/val.

Для отдельной конвертации COCO Instance Segmentation в YOLO
Detection/Segmentation можно запустить `py -3 convert_coco_to_yolo.py`.
Перед запуском задайте в начале скрипта `COCO_JSON`, `IMAGE_DIR`, `OUTPUT_DIR`,
`VAL_RATIO` и `RANDOM_SEED`. Скрипт использует только стандартную библиотеку
Python, пропускает отсутствующие изображения с предупреждением и создаёт
пустые метки для изображений без объектов. Полигоны сохраняются в YOLO
Segmentation, а для объектов без полигонов используется bbox в формате YOLO
Detection. В одном наборе поэтому могут присутствовать оба типа строк разметки.

Настройте число эпох, размер изображения, batch и устройство (авто, CPU или
обнаруженный GPU), затем запустите обучение. Приложение проверяет, видит ли
установленный PyTorch CUDA-устройство, показывает версию PyTorch и список
доступных GPU. В режиме «Авто» выбирается GPU, если CUDA доступна, иначе CPU.
Если GPU выбран вручную, но CUDA-драйвер или CUDA-сборка PyTorch недоступны,
задача предупредит об этом и продолжится на CPU вместо завершения с ошибкой
`Invalid CUDA device`. Если NVIDIA GPU установлен, но PyTorch показывает
`torch.cuda.is_available() == False`, установите сборку, подходящую драйверу и
ОС, через официальный селектор <https://pytorch.org/get-started/locally/>.
Интерфейс показывает прогресс и журнал,
позволяет запросить остановку после текущей эпохи и скачать `best.pt`.
Результаты сохраняются в `inspection_data/training/runs`, данные задач — в
`inspection_data/training/jobs`. Обучение выполняется на компьютере, где
запущен Streamlit; GPU доступен только при установленном совместимом PyTorch
с CUDA. Загружайте только доверенные `.pt`-файлы и проверенные наборы данных.

Дообученные веса не подменяют рабочую модель автоматически. Чтобы применять
новый checkpoint для обычного анализа, укажите его через `YOLO_MODEL_PATH`
при запуске Node-сервера и перезапустите сервер. Страница Streamlit работает
отдельно от Cloudflare Tunnel и не становится общедоступной при публикации
основного Node-сайта.

## Доступ через интернет

Для временной публикации предусмотрен Cloudflare Tunnel: установите `cloudflared` и запустите `start-public.ps1`; для остановки используйте `stop-public.ps1`. Скрипт генерирует случайный пароль для страницы входа и защищает весь сайт и API сессионной авторизацией. Нужны исходящие TCP/UDP-соединения на порт 7844; доступность туннеля зависит от сети. URL временный и действует только пока запущены Node.js и `cloudflared`. Не открывайте порт сервера напрямую в роутере.
